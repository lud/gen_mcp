# Resources on the 2025 compat transport

Reopens feature 017 on the terms it set for itself: resources stayed unbuilt
until a user reported needing them, and then the answer is "a `Translate`
clause plus a route, one spec per method family". The report came in as
[PR #79](https://github.com/lud/gen_mcp/pull/79) from an outside user running
the compat transport in production behind Claude Desktop, where the MCP Apps
extension fetches a tool's `_meta.ui.resourceUri` bundle with `resources/read`.

## Merged — PR #79

`resources/list`, `resources/templates/list` and `resources/read` on the
compat transport. Reviewed against the feature's own plan and merged as
`6613a51`:

- the three list methods share a `paginated_request/3` helper in `Translate`;
- results drop the 2026-only `resultType`, `cacheScope` and `ttlMs`;
- a missing resource is answered `-32002`, the code the 2025 spec defines,
  instead of the `-32602` spec 005 moved the 2026 core to;
- the handshake strips `subscribe` from the downgraded resources capability.

Verified during review, beyond the PR's own tests: `Suite` builds capability
flags as plain maps, so the `Map.delete/2` on the capability is safe; the
`V2607` resource entities (`Resource`, `ResourceTemplate`,
`Text`/`BlobResourceContents`) are field-subsets of 2025-11-25, so nothing
2026-only leaks through the passthrough; and stripping `subscribe` is the only
option, since 2026 replaced `resources/subscribe` with
`SubscriptionFilter.resourceSubscriptions`, a URI list fixed when the listen
opens — which the compat `GET` stream opens once, with flags only.

## Method-not-found stops borrowing 404 — done

The PR's own problem statement was that a capability advertised but not served
answers `-32601` as HTTP `404`, which in 2025 means "session gone, start a new
one". The PR fixed the symptom for resources by not advertising them falsely;
the status itself was the general bug, and it still hit `prompts/*` (still
advertised, still unrouted), `resources/subscribe` and anything else.

The unrouted-method clause in `V2511.Impl.route/4` now answers
`{:unsupported_method, method}`, which `GenMCP.Error` already maps to `-32601`
at HTTP `200` (`error.ex:214`), so `404` on this transport means one thing
only. The clause looks the session up first, unlike `ping` and
`logging/setLevel`: that is what keeps the two answers distinguishable when a
session dies mid-probe.

`prompts` therefore stays advertised in the handshake and answers `-32601` at
`200`, which a client can read and carry on from. Serving `prompts/*` for real
is the next method family, if a user reports needing it.

Guide `090.upgrading-to-v2.md` lists the resources methods and the `200` in its
surface warning.
